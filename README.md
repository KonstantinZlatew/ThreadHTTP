# Прост асинхронен HTTP сървър на Python

## 1. Въведение

Настоящият проект представлява имплементация на прост уеб/HTTP сървър, написан на езика **Python**, който приема и обработва клиентски заявки чрез **асинхронен модел**. Сървърът използва ниско ниво на достъп до мрежовите ресурси посредством функциите `socket`, `bind`, `listen`, `accept`, `recv` и `send`. Основната му цел е да демонстрира как може да се реализира базов HTTP сървър без използване на готови библиотеки за парсване на HTTP протокола.

Сървърът чете входните заявки байт по байт, разпознава HTTP метода (GET или POST), хедърите и body частта. След това връща коректен HTTP отговор според валидността на заявката:
- Отговор **OK** при правилно подадена заявка.
- Отговор **ERROR** при невалидна или прекалено голяма заявка.

Проектът е създаден в съответствие с изискванията на задачата, включително обработка на множество клиенти паралелно чрез асинхронна реализация (`asyncio`), устойчивост на невалиден вход и запис на лог файл с информация за всички получени заявки.

---

## 2. Технологии и използвани модули

Проектът е разработен изцяло на **Python 3.12** и не използва външни библиотеки.  
Използвани са само стандартни модули:

- `socket` – за създаване и управление на TCP сървъра на ниско ниво;
- `asyncio` – за асинхронна обработка на множество клиенти едновременно;
- `datetime` – за запис на времеви печат при логване на заявките;
- `logging` – за запис на информация във файл;
- `traceback` – за коректно отчитане и логване на грешки при изпълнение.

Сървърът е тестван и работи както под **Windows**, така и под **Linux**. Под Linux може да се възползва от `epoll`, докато под Windows се използва стандартният механизъм `select`.

## 3. Логика на работа

### 3.1 Основна функция `run()`

Функцията `run()` е началната точка на програмата. Тя:
1. Създава TCP сокет чрез `socket.socket()`.
2. Свързва го към избран порт (по подразбиране 9090).
3. Поставя сокета в режим на слушане чрез `listen()`.
4. Използва основния асинхронен цикъл (`asyncio.get_event_loop()`), който чака входящи връзки.
5. При всяка нова връзка създава нова асинхронна задача `handle_client()`.

Това позволява на сървъра да обработва няколко клиента едновременно без блокиране на изпълнението.

---

### 3.2 Функция `handle_client(reader, writer)`

Тази функция отговаря за обработката на конкретен клиент. Основните стъпки са:
1. Чете входните данни по байтове чрез `await reader.read()`.
2. Проверява дали заявката е по-дълга от 10 MB. Ако е така, я прекъсва и връща `ERROR`.
3. Опитва се да разпознае първия ред от заявката и да извлече HTTP метода (GET или POST).
4. Ако парсирането е успешно, връща коректен HTTP отговор с код 200 и съдържание “OK”.
5. Ако заявката е невалидна, съдържа нечетими символи или е прекалено голяма, връща отговор с код 400 и съдържание “ERROR”.
6. След приключване на обработката, информацията за заявката се записва в лог файл чрез функцията `log_request()`.

---

### 3.3 Функция `log_request(data, addr)`

Тази функция се грижи за записването на всички входящи заявки в лог файл (`server.log`). Всеки запис съдържа:
- Времеви печат (timestamp);
- IP адрес на клиента;
- Извлечен HTTP метод;
- Всички хедъри и стойности;
- Body на заявката (ако има такова).

Примерен лог запис:

[2025-10-27 14:23:11] 127.0.0.1:52314
Method: GET
Headers: Host: localhost
Body: (none)
yaml
Copy code

## 4. Паралелна обработка

За да бъде постигната паралелност, сървърът използва асинхронни функции (`async def`) и `asyncio.create_task()`. По този начин всяка нова връзка се обработва в собствена задача, без да блокира основния поток. Това осигурява ефективно и мащабируемо обслужване на множество клиенти едновременно.

---

## 5. Защита срещу невалидни и прекалено големи заявки

В съответствие с условието на задачата, сървърът е устойчив срещу следните случаи:
- Невалиден HTTP request (случайни байтове, невидими символи);
- Първи ред или хедър с дължина над 10 MB;
- Body по-голямо от 10 MB;
- Невалидна UTF-8 кодировка.

При тези случаи програмата не забива, а връща отговор `ERROR` и продължава да работи стабилно.

## 6. Тест на сървъра

### 6.1 Стартиране на сървъра

За да стартирате сървъра, използвайте командата:

```bash
python server.py
Ако порт 80 е зает, може да смените порта в кода (например 9090).
```

### 6.2 Тест с браузър

След стартиране, отворете браузър и въведете:

cpp

http://127.0.0.1:9090

Ще получите следния отговор:

nginx

OK

### 6.3 Тест с curl

Може да изпратите тестови заявки чрез терминал:

```bash
curl http://127.0.0.1:9090
curl -X POST -d "Hello Server" http://127.0.0.1:9090
```
Изход:

```makefile

Content-Length: 2
Connection: close

OK
```

### 6.4 Автоматичен тест чрез tester.py

В проекта има и скрипт `tester.py`, който изпраща серия от заявки:

Случайни байтове (невалидни заявки);

Прекалено големи заявки (>10MB).

Целта е да се провери дали сървърът остава стабилен и отговаря правилно.

## 9. Ограничения и възможности за подобрение
Текущата версия на сървъра не поддържа:

- HTTPS (шифрирана комуникация);

- Сервиране на статични файлове;

- Пълно парсване на URI параметри.

Възможни подобрения:

- Добавяне на HTTPS чрез библиотеката ssl;

- Подобряване на парсера за по-добра валидация на HTTP заявките;
